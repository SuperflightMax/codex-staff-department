# Как подключиться к реальному Codex

Этот документ — техническая подсказка для первого запуска, не обещание наличия каждого инструмента в установленном приложении.

## Сначала имеющееся

Director проверяет доступные межсессионные инструменты локального Codex и переиспользует рабочий способ. Требуются независимый чат, сообщения по ID, чтение истории и удаление. Имена действий надо получить из их настоящих схем, не выдумывать по названиям в чате.

Роли в `roles/` — инструкции, **не** нативные конфигурации субагентов. Назначение роли текстом не создаёт сессию, не меняет модель и не даёт дополнительных инструментов.

## Официальный технический маршрут

App Server документирует `thread/start`, `thread/resume`, `turn/start`, `turn/steer`, `thread/read`, постраничные `thread/turns/list` / `thread/items/list`, `thread/delete` и `model/list`. Архивирование и удаление различаются. Схему своей версии можно получить командой:

```sh
codex app-server generate-json-schema --out ./schemas
```

Источник: [OpenAI, App Server](https://learn.chatgpt.com/docs/app-server), проверено 19.10.2026.

`AGENTS.md` собирается при запуске; правка файла не гарантирует обновления живой сессии. Поэтому Refresh доставляет изменение явно. Источник: [OpenAI, инструкции AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

Не заменяй встроенные инструкции Codex файлом роли через `model_instructions_file`: это другой смысл настройки. Источник: [OpenAI, конфигурация](https://learn.chatgpt.com/docs/config-file/config-reference).

## Требования нашего адаптера, если он понадобится

- Создавать независимый постоянный root-thread, не fork и не внутреннего субагента. Использовать нужный каталог проекта и тот же рабочий контур Codex, который показывает приложение.
- Инструкции роли/общие правила передавать поддерживаемым способом. Не перезаписывать глобальный AGENTS.md, настройки всех проектов или служебную БД Codex для одного работника.
- Для живого хода держать соединение/процесс, принимающий его события. Не выдавать стартовый ID за окончание работы. Если модель запросила инструмент/разрешение, обслужить предусмотренный запрос, а не оставить ход молча висящим.
- Возвращать результат правильному заказчику. Не давать двум клиентам одновременно запускать конкурирующие ходы одного работника.
- Выбор модели применять технически. Использовать разрешённые настройки из MODELS.md; успешное перечисление каталога ещё не заменяет успешный реальный вызов.
- При завершении сохранять историю до удаления. Не чистить произвольные файлы внутри `.codex` и не останавливать чужие процессы.

Один небольшой локальный скрипт допустим, если штатные инструменты не дают нужного вызова. Файл со схемой временный и не обязан попадать в Git. Не разворачивай отдельную постоянно думающую систему и не изучай весь API вместо одного рабочего прохода.

Если текущая версия не даёт нужной функции, сообщи точное ограничение и путь её получения. Не меняй продуктовую цель молча на «будут субагенты» или «пусть Max переносит сообщения». Отдельно проверить видимость чата в приложении и возможность повторного обращения: из этой веб-сессии компьютер Max не проверялся.
