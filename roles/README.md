# Каталог ролей

Здесь **профессии, не обязательный состав команды**. Полная рабочая инструкция сотрудника складывается из [Playbook](../PLAYBOOK.md), одной роли, применимых проектных дополнений и конкретного поручения. [Модель/reasoning](../MODELS.md) выбираются отдельно. Размножать определения общих принципов в каждом задании не надо.

## Архитектор

[Архитектор — проектирование и проектная истина](architect.md) — универсальная роль для чата, которому Max поручил проектирование. Здесь описаны вход через Playbook, выбор репозитория проекта, рабочее место, документация и сохранение контекста. [Короткая отсылка для пользовательских инструкций](../architect/CUSTOM_INSTRUCTIONS.md).

Наличие описания в каталоге не запускает архитектора через Staff Director автоматически. Это роль собеседника Max, не дополнительный обязательный уровень производственной команды. Контекст конкретного проекта находится в `architect/` **его** репозитория.

## Сотрудники кадровой службы

| ID | Роль | Что от неё нужно |
|---|---|---|
| staff-director | [Staff Director](staff-director.md) | Выдать, учесть, обновить, забрать сотрудника. |
| cto | [CTO](cto.md) | Превратить согласованный этап спецификации в достигнутую цель. |
| lead | [Lead](lead.md) | Организовать конкретную команду и выполнение её задач. |
| builder | [Builder](builder.md) | Реализовать и исправить. FE/BE и стек — специализации, не новые общие роли. |
| technical-qa | [Technical QA](technical-qa.md) | Проверить реальную функцию и затронутые контракты. |
| usability-qa | [Usability QA](usability-qa.md) | Проверить, что человеку действительно удобно выполнить цель. |
| visual-qa | [Visual QA](visual-qa.md) | Проверить видимый результат и соответствие выбранному визуальному решению. |
| inspector | [Inspector / Reviewer](inspector.md) | Независимый свежий взгляд при конкретном основании. |
| game-designer | [Game Designer](game-designer.md) | Спроектировать и настроить механики игры, интерес, сложность, игровой баланс и ощущения от управления. |
| ux-designer | [UX Designer](ux-designer.md) | Спроектировать человеческий опыт взаимодействия, в том числе поведение во времени. |
| ui-designer | [UI Designer](ui-designer.md) | Спроектировать конкретные экраны, компоновку, элементы и визуальные состояния интерфейса. |
| concept-artist | [Concept Artist](concept-artist.md) | Найти подходящее творческое направление, референсы и концепт. |
| asset-artist | [Asset Artist](asset-artist.md) | Изготовить применимые материалы в утверждённом направлении. |
| devops | [DevOps](devops.md) | Подготовить/исправить нужное окружение и инфраструктуру. |
| release-engineer | [Release Engineer](release-engineer.md) | Выпустить конкретную принятую версию и проверить её работу в среде. |
| worker | [Worker](worker.md) | Точные механические действия: упаковать, скопировать, перенести, убрать. |
| documentation-steward | [Documentation Steward](documentation-steward.md) | Поддержать актуальную документацию без перепридумывания продукта. |
| investigator | [Investigator](investigator.md) | Разобрать причинную цепочку сложного/повторяющегося сбоя. |
| researcher | [Researcher](researcher.md) | Найти факты и сравнить варианты для конкретного решения. |

**Lead заменяет прежнее название Orca/Орка.** Отдельного Consultant нет: консультация — функция CTO. Универсальная инструкция архитектора — [roles/architect.md](architect.md); [architect/START_HERE.md](../architect/START_HERE.md) хранит вход только в проект Staff Department.

Название «Visual Designer» слишком неоднозначно для отдельной универсальной роли: человеческий опыт — UX Designer, конкретные экраны и UI — UI Designer, творческое направление — Concept Artist, изготовление финальных материалов — Asset Artist. Роли описывают компетенцию, а не обязательное количество сотрудников. Запрос трактуется по необходимому результату, не по модному титулу.

Max может обратиться к любому специалисту напрямую, особенно к UX Designer, UI Designer и Concept Artist. Тогда Max — заказчик; не требуется изобретать CTO ради одного разговора.

Для сложного поручения роль получает цель, нужный контекст и границы. Для Worker зачастую достаточно точных входов и результата. Карточка роли не заменяет настоящее поручение; поручение не повторяет всю карточку.
