# Модель и глубина рассуждения

Политика пилота, а не обещание доступности моделей в любом аккаунте.

## Выбор

Проверенная Max отправная точка — **GPT-5.6 Sol**. Для этого пилота GPT-6.x не выбирать без нового явного решения Max. Точное техническое имя модели и поддерживаемые уровни выясняет Director в установленном Codex; человеческое название не превращать в угаданный API ID.

Сначала используй уже разрешённую рабочую модель. Более дешёвые замены испытываем по реальной полезности, не запускаем сравнительные соревнования перед каждым ZIP. Если разрешённая модель недоступна, проверь реальный доступ и предложи конкретную альтернативу; не подменяй её молча запрещённой.

CTO определяет требуемую глубину для заданий **исполнителей**; Director выбирает и реально применяет поддерживаемую настройку. Сам **CTO создаётся с reasoning `max`**. Менять его на более низкий уровень без прямого решения Max нельзя. Для прямого запроса Max без CTO директор использует таблицу ниже. Запись «ты теперь более умная модель» не меняет конфигурацию сессии.

## Стартовые уровни

| Роль | Обычный старт | Когда повышать |
|---|---|---|
| Staff Director | medium | Несовместимые инструкции, восстановление после сбоя. |
| CTO | **max** | Базовый режим для обсуждений и принятия решений с Max. Не понижать без решения Max. |
| Lead | medium | Не повышать вместо обращения к CTO за решением. |
| Builder | medium | Конкретная сложная реализация/диагностика; не весь проект. |
| Technical QA | medium | Неочевидный контракт или неоднозначная причина. |
| Usability QA | **xhigh** | max только если действительно нужно сложное продуктовое суждение. |
| Visual QA | medium | Неоднозначный визуальный дефект. |
| Inspector / Reviewer | **xhigh** | max для особо сложного независимого ревью по запросу. |
| Game Designer | **xhigh** | max при сложном проектировании механик и баланса по запросу. |
| UX Designer | **xhigh** | max при сложном совместном проектировании по запросу. |
| UI Designer | **xhigh** | max при сложном обсуждении визуального решения и экранов по запросу. |
| Concept Artist | **xhigh** | max при действительно сложном выборе творческого направления. |
| Asset Artist | medium | Сложное исполнение утверждённого направления. |
| DevOps / Release Engineer | medium | Реальная неоднозначная эксплуатационная проблема. |
| Worker | low | medium, если low отсутствует или не справляется. |
| Documentation Steward | medium | Конфликт источников передать владельцу истины. |
| Investigator | **xhigh** | max при неоднозначном системном расследовании. |
| Researcher | **xhigh** | Это режим обсуждения и аналитических выводов, не механический сбор ссылок. |

**Разговорные/консультативные роли начинают не ниже `xhigh`; CTO — сразу `max`.** `high` не используется как старт для содержательного обсуждения с Max. Операционные роли (Lead, Builder, Worker и т. п.) сохраняют более экономные настройки, потому что их работа другая.

Это рабочие настройки, их калибруем по опыту. Director проверяет реальные доступные уровни. Если `max` для CTO или `xhigh` для разговорной роли не поддерживается, **не понижать молча**: сообщить Max и согласовать допустимую замену. Фактические настройки сохранять в реестре. Повышение остальных ролей до `xhigh/max` — адресное решение, а не стандарт для всех.

Не повышай reasoning автоматически после любого сбоя. Сначала отличи нехватку понимания от неверного задания, окружения, отсутствующего инструмента или плохих данных. Иногда нужен ясный вопрос, другая роль или свежий контекст, а не более долгие размышления того же агента.

При изменении этой политики Director проверяет **уже созданных сотрудников**. Для действующего CTO требуется реальная смена параметра на `max`, если её поддерживает текущий Codex; текстовое уведомление не меняет reasoning. Если менять нельзя, сохранить состояние и согласованно заменить CTO без потери работы. В учёте достаточно: роль, фактические model ID и effort, причина отклонения от обычного старта. Политику моделей хранить здесь, не копировать таблицу во все роли.
