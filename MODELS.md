# Модель и глубина рассуждения

Политика фабрики по решению Max от **26 октября 2026**. Это требования к выбору настроек, не обещание доступности моделей и уровней в любой среде. Канон политики находится здесь; таблицу не копировать во все роли.

## Кто выбирает и кто применяет

**Max задаёт общую политику, разрешённые модели и особые режимы работы. CTO выбирает нужную глубину для заданий своей команды в этих границах. Staff Director технически применяет настройку, проверяет фактическое значение и сохраняет его в реестре.** Lead передаёт кадровый запрос в пределах выбора CTO; не снижает минимумы самостоятельно.

Если CTO/заказчик не указал настройку или сотрудника нанимают ещё без конкретной задачи, Director использует старт своей роли из таблицы. Отсутствие задачи или специализации не повод назначить более низкий reasoning и не блокирует найм. Director не выбирает меньший уровень ради экономии вопреки политике или явному запросу.

## Минимумы профессиональной работы

**Любая роль с профессиональной ответственностью работает не ниже High (`high`).** Это относится и к организации, реализации, проверке, эксплуатации, исследованию и документации. Прежние старты `medium` для Lead, Builder, QA, Staff Director, Asset Artist и других профессиональных ролей больше не действуют.

**Все художники и дизайнеры — не ниже XHigh (`xhigh`).** В том числе Concept Artist, Asset Artist, Game Designer, UX Designer и UI Designer, а также их проектные специализации. Изготовление материалов по выбранному направлению не является механической работой: сохранение качества и замысла требует профессиональных решений. CTO не понижает такие роли до High ради простоты конкретного поручения.

**Для Builder и всех разновидностей QA CTO выбирает High или XHigh по сложности, связанности задачи и необходимому суждению.** Более высокий поддерживаемый режим также допустим при необходимости. У Usability QA сохраняется обычный старт XHigh, но CTO может явно выбрать High; общий нижний предел для QA — High.

Единственное обычное исключение ниже High — **Worker, действующий практически как скрипт**: точные инструкции, известные входы и операции, почти нет содержательного выбора. Для него допустимы Low/Medium. Название Worker само по себе исключения не даёт: если нужно интерпретировать требования, выбирать подход, диагностировать неоднозначную ситуацию или оценивать качество, работа требует не ниже High либо передачи подходящему специалисту. При неизвестном будущем поручении Worker начинает с High; снижать можно для уже определённой механической операции.

## Обычные старты вне явно назначенного опыта Max

| Роль | Старт | Выбор для конкретной работы |
|---|---|---|
| Staff Director | **high** | Повышать при необходимости, не ниже High. |
| CTO | **max** | Прежняя индивидуальная настройка сохраняется вне отдельного решения Max; текущий опыт ниже прямо задаёт XHigh. |
| Architect | **xhigh** | Содержательное проектирование и обсуждение; не ниже общего минимума High. |
| Lead | **high** | Повышать по сложности координации; reasoning не заменяет обращение к CTO за решением вне полномочий. |
| Builder | **high** | CTO выбирает High/XHigh по задаче. |
| Technical QA / Visual QA | **high** | CTO выбирает High/XHigh по задаче. |
| Usability QA | **xhigh** | CTO может выбрать High/XHigh; не ниже High. |
| Inspector / Reviewer | **xhigh** | Сохраняется прежний высокий старт для независимого ревью. |
| Game Designer / UX Designer / UI Designer | **xhigh** | XHigh — минимум, не только старт. |
| Concept Artist / Asset Artist | **xhigh** | XHigh — минимум, включая производственную подготовку материалов. |
| DevOps / Release Engineer | **high** | Повышать при необходимом сложном суждении, не ниже High. |
| Documentation Steward | **high** | Конфликт источников передавать владельцу истины; не разрешать его понижением глубины. |
| Investigator / Researcher | **xhigh** | Сохраняется прежний старт для содержательного исследования. |
| Worker | **high** без конкретной операции; **low/medium** для механической | Исключение определяется самой работой, а не должностью. |

Для новой роли, не названной в таблице, действует общий минимум High; для любой художественной или дизайнерской специализации — XHigh. Более строгий явно выбранный Max режим имеет приоритет над обычным стартом. Точные технические обозначения и поддерживаемые уровни Director проверяет в используемом runtime; не считать `max` и `xhigh` синонимами по догадке.

## Текущий опыт: GPT-6.1 Sol + XHigh

**Max сообщил, что переводит работающие команды на GPT-6.1 Sol и XHigh для всех участников, чтобы посмотреть на изменение результата.** Это явное разрешение использовать 6.1 Sol: прежний запрет выбирать GPT-6.x без нового решения Max больше не применяется к этой модели.

В командах, на которые распространяется этот опыт, настройка **GPT-6.1 Sol + XHigh** имеет приоритет над таблицей, включая прежний старт CTO `max` и возможность Low/Medium у Worker. Новые или заменяющие сотрудники такой команды получают тот же режим. Пока Max не изменил режим опыта, CTO не возвращает Builder или QA на High только потому, что обычная политика это допускает. Это не утверждение, что всем ролям навсегда нужен XHigh или что прежние ошибки уже объяснены глубиной рассуждения.

Вне явно назначенного опыта действует таблица и согласованный для проекта выбор модели. GPT-5.6 Sol остаётся разрешённой прежним решением, GPT-6.1 Sol разрешена новым; другие модели не подставлять без решения Max. Не угадывай технический model ID из человеческого названия. Для отсутствующей или неподдерживаемой настройки назови конкретное ограничение и предложи допустимый вариант; не понижай незаметно и не утверждай, что требуемая конфигурация применена, если это не подтверждено.

## Применение и действующие сотрудники

Фактические model ID и reasoning/effort должны быть параметрами сессии, а не фразой в её промпте. При найме Director проверяет применённую настройку и записывает её в существующий кадровый реестр. Требуемое, отправленное и подтверждённое значение не смешивать. Один лишь сбой не доказывает недостаточность reasoning: причиной могут быть задача, инструменты, данные или организация работы.

**По текущему поручению обновляется политика, но массовая перенастройка уже существующих сотрудников не запускается.** Max выполняет свой текущий перевод команд сам. Публикация этого файла не означает, что живые сессии уже изменены, и не даёт поручения их перезапускать или создавать замены.

**Отложенная тема для отдельного решения:** как Director сверяет фактические модели и reasoning всех действующих сотрудников с актуальной политикой и при необходимости меняет именно конфигурацию, а не только текст инструкций. Возможность изменения параметров существующей сессии и безопасной передачи при необходимости замены нужно проверить отдельно. Сейчас этот механизм не разрабатывается, обход персонала и экспериментальное переключение не выполняются; обычное обновление текстов ролей не объявляется сменой модели/reasoning.
